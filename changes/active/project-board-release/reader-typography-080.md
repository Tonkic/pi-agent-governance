# 0.8.0：正文优先的文档阅读

## 授权与参考

用户要求参考排版材料与字体网页改善糟糕的阅读体验，并升级新版本。经明确选择：**0.8.0仅同步源码与安装包，不创建标签或GitHub Release，不发布市场/npm，不自动安装**。原1.x发布政策、安全权限及总体宿主检查阻塞不变。

参考用户提供的《排版的艺术：一条很长很长的路》全文摘录，及 [Karlbaey字体文章](https://re.karlbaey.top/articles/some-inexplicable-fonts-in-golang-coding/)。参考网页通过只读HTTP实际200获取，题为《我对各种字体的看法（Go语言版）》，内容含Noto Sans、Fira Code、微软雅黑可读性讨论、折叠目录和正文代码层次。

内置Browser首次无法进入当前会话前台，未声称实际目视参考站；HTTP源码分析不等于浏览器目视。取其正文优先、安静字体、阅读行宽/行距和配角退让原则，不复制网页文章/截图/字体文件，不加载其CDN或图片。

## 目标与边界

| Before | After（本项目标） | Why |
| --- | --- | --- |
| 阅读前先穿过顶部管理提示 | 阅读页独立紧凑工具区，其他管理页面保持 | 正文先进入视线 |
| 14px正文和被侧栏挤压的行宽 | 系统无衬线、17–18px默认字号、受控行宽和段落间距 | 连续长文更舒适 |
| 手机先滚过文件库与目录 | 文件库/目录按需展开，正文优先 | 降低操作和滚动成本 |
| 技术Markdown表格等纯文本杂乱 | 补安全常用格式与局部横滚 | 不以可执行HTML换取排版 |

只读固定文档范围、路径/敏感/链接保护、256KiB/500文件/4000条目/8层限额、原HTML/链接/图片字面文本不执行和epoch/request/owns迟到保护保持。无依赖/权限或宿主会话/模型能力变化；不恢复暂停的桌面开发。
