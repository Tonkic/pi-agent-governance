# 只读Git提交图与二级详情

## 范围

- 用户确认只读方案并要求开始实现：最新在上、早期在下，真实分支/合并连线，节点进入二级提交详情/文件差异，返回保留图位置。
- Git页新增提交历史默认标签，保留原受管工作区与验证卡片；不执行checkout/merge/reset/fetch/push，不联网，不升版本/重提市场/自动安装。
- 独立读取模块git-history.ts与renderer/git-history.ts，经固定governance.gitHistory list/detail/diff通道；原Git写入登记模块不变。
- 默认每页100提交、最大5000，64并行图线；快照绑定HEAD/refs，变化需手动刷新。浅克隆/分页边界明确提示，不把未加载底部冒充初始提交。
- 详情相对第一父提交比较，根提交对空树；元数据/文本均textContent，敏感/链接/二进制/超大差异受限。详情最多缓存16项、差异8项。

## 实现与检查

- 后端独立worker git-history-data 在受管工作区实现模块及真实Git测试，父协调Agent负责UI/接线/测试发现/清单/说明；无同路径并发写入。
- 已执行一次前端构建通过。新增真实Git浏览器fixture覆盖分支/合并/标签、超过100提交分页、详情/文件差异、返回位置/焦点、双语明暗三宽度、离线/错误/迟到/epoch。
- 最终集成、完整检查、预算、官方包及实际main/CI结果待更新。

## 边界

- 源码和包内Git配置仍限可信仓库，不防恶意并发。历史模块不初始化治理数据；原受管查询的登记目录行为保留。
- 自动浏览器/截图不等于实体触屏、人工目视或已安装宿主完整E2E；原总体阻塞和暂停桌面保留，整体任务不close。
