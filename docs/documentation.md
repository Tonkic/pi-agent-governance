# 更新项目文档

在原宿主会话明确要求Agent整理当前项目文档，不是更新插件版本。保留该会话的模型、思考和历史；浏览器只展示项目/文档数据，不提供另开文档Agent或模型选择按钮。

## 写入范围

- `docs/`：当前用途、用法和必要限制，按 Microsoft Writing Style Guide 写作。
- `notes/`：像 Git 记录一样，简记每次新增、删除、修改、实际结果和踩坑。通常每次 4–8 行，不贴完整日志。
- 根 `README.md`、`AGENTS.md`：只补必要入口或索引，保留既有约束。

先读项目指令、STATE 和相关代码，按现状更新，不从历史猜测授权。已有其他写入任务时停止。旧说明迁移时核对链接；保留历史证据原文。外部要求固定位置或归属不明的文件，先询问而非强行搬走。

文档整理默认不修改功能代码、生成产物、版本、STATE、看板或架构，也不自行提交、合并、推送或安装。额外动作以当前明确授权为准；统一入口不再新建operations会话记录。

## 渐进式披露

1. 短索引按问题链接专题，Agent 不必顺序读全部文档。
2. 专题先给结论和常用操作，再给具名的参数、规则与限制章节。
3. 只在追溯时读 Notes 归档；详细差异由 Git 保存。

专题原则上不超过 100 行。变长时按独立问题拆分并回链，不堆重复说明或空模板。简洁时整篇读取也可以，不把披露层级变成强制打卡。

## 检查与限制

运行文档差异和链接检查，报告实际结果及阻塞，通过即可完成，不另设验收。在原宿主停止任务不会撤销已写入文件。

需要已批准范围和实际宿主工具权限；不再为网页授予models.list或Agent启动权限。提示词不是安全沙箱，不与其它开发会话并发写入同项目。
