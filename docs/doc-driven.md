# 文档驱动开发：第一阶段

人读说明，测试验证具体场景。第一阶段用「工作区切换」试点，新增行为关联和只读验证状态，不改变 STATE 的任务授权规则。

## 查看行为与证据

在顶部「项目任务」选择「行为文档」。正文显示当前项目的自然语言说明，按 Microsoft 标准保持具体、简短；测试和实现路径藏在「覆盖范围与验证证据」中。

- 未验证：没有本机检查记录。
- 关联隔离浏览器场景通过：全部关联场景已执行，检查成功，文档及关联文件内容仍匹配。
- 覆盖不完整：关联场景缺失或被跳过，不能算通过。
- 检查失败：最近一次关联检查失败，旧通过记录不能遮盖它。
- 内容已变：文档、关联配置、实现或测试变化，或记录属于另一工作区。
- 进行中/待核对：检查已启动或中断，不能使用上次通过代替本次结果。

「通过」只涵盖已列场景，不能证明整篇说明无遗漏。当前运行使用真实临时项目后端、隔离Chromium和模拟宿主事件，不代表本机插件或SSH验收。状态带测试时间、基准提交及是否为工作树快照；它不是独立签名或防恶意修改的证明。

## 运行项目检查

本仓库在可信、独占工作区中运行：

```powershell
npm run check:behaviors
```

需要配置Playwright和PI_BROWSER，见 [开发](development.md)。命令先构建，再执行固定的 `test/browser.cjs`。面板只读，不执行文档提供的命令，不后台轮询、不启动收费Agent。

测试断言通过后才报告场景编号。检查器核对本次运行ID、完整结束标志、进程结果和所有关联场景，再写入 `.governance/behavior-evidence.json`。运行前后文档/关联文件或HEAD变化则拒绝替换证据。失败产生失败记录；缺失场景产生不完整状态，命令返回失败。

同一项目一次只允许一个检查；运行锁为 `.governance/behavior-check.lock/`。启动前先保存进行中记录，正常读锁竞争最多等待五秒，不删别人的锁、不重跑测试。进程异常退出时先核对没有检查进程，再人工处理遗留锁；不能恢复为旧的通过状态。

验证记录为Git忽略的本机产物，绑定绝对工作区和内容快照，不进安装包。复制仓库或换机器不会自动得到「已验证」，应重新实际检查；不要手写通过记录。关闭模态框后再次打开会读取最新结果。

## 关联约定

自然语言正文在 `docs/behavior-workspace.md`。小节标题为 `### WS-001 — 标题`，正文不写测试语法。技术配置在 `docs/behavior-bindings.json`：每个行为关联文档、稳定场景ID和相关实现/测试文件；面板安全读取并以纯文本展示，不渲染项目HTML。

最多50条行为、每项20场景/20文件、总计60文件/500000字符。路径复用治理内核的敏感路径和符号链接限制。新增有编号的说明小节但没有关联时检查报错。未编号的用途/解释不自动声称有测试覆盖，仍需人工核对。

当前检查器只提供本插件仓库的固定浏览器运行器。其它项目可以配置文档和读取同格式证据，但不能把这里的试点命令当通用测试调度器；后续再添加受控运行器，不接受任意shell命令。

## 后续阶段

本阶段只证明「可读说明→关联场景→实际结果→可读状态」闭环。文档提议、人工批准版本和任务引用绑定留到后续实现；修改文档不等于批准代码变更，STATE仍决定范围。不要把提议提前写成已实现行为。
